## 좌석 지정 방법

| 방식 | 입력 예 | 판정 |
|:---|:---|:---|
| **좌석 직접 지정** | `G22,G23 \| F22,F23` | 콤마로 묶인 한 그룹이 **전부** 비면 알림 (`\|` 는 대안) |
| **명당 자동 추천** | 인원 2, 상위 20% | 명당 영역 안에서 붙어있는 2석이 나면 알림 |
| **연속 N석** | 인원 2, 선호 열 `F,G,H` | 같은 열에서 **붙어있는** 2석 (통로로 끊기면 별개) |
| **아무 자리나** | 인원 2 | 잔여석이 2석 이상이면 알림 |

### 좌석 종류로 좁히기

세 브랜드 모두 좌석 종류를 알려주므로 **"스위트 리클라이너만", "빈백·소파베드만"** 처럼
노릴 자리를 좁힐 수 있습니다. 마법사가 실제 좌석표를 받아 거기 있는 종류만 보여줍니다.

```
어떤 좌석을 노릴까요
 ◉ 스탠다드(리클라이너)      164석
 ◉ 스위트(리클라이너)         36석
 ○ 빈백                     26석
```

고른 종류 밖의 자리는 나간 자리로 취급하므로 연속석·명당 판정도 그 안에서만 이뤄집니다.

> [!WARNING]
> 리클라이너관은 통로 때문에 좌석 번호가 띄엄띄엄합니다 (21관 A열 = 5, 6, 7, 8, 12, 13 …).
> 없는 번호를 넣으면 알림이 영원히 오지 않으므로, **입력한 좌석이 그 상영관에 실제로
> 있는지 대조**한 뒤 없으면 다시 물어봅니다.

## 명당 자동 추천

좌석 번호를 직접 고르지 않아도 됩니다. API의 `SweetSpotYN` 필드는 전 좌석이 `N` 이라 쓸 수 없어
좌석 좌표로 직접 계산합니다. `X` 는 좌우, `Y` 는 스크린에서 멀어지는 방향(A열이 최소값)임을
실측으로 확인하고, `좌우 정중앙 · 앞에서 62% 뒤` 를 기준점으로 거리 점수를 매깁니다.

```
G    ■■■■■■■■■■■◆◆·◆■■■■■■■■■■■
I    ■■■■■■■■◆◆◆·◆·◆·◆◆■■■■■■■■
K    ■■■■■■■■◆◆◆◆◆·◆◆◆◆■■■■■■■■
L    ■■■■■■■■◆◆◆◆◆◆◆◆◆◆■■■■■■■■
   ◆ 명당 49석 가능   ■ 그 외 가능   · 불가
```

> [!NOTE]
> 월드타워 21관에서는 이 계산으로 `G22, G23, G21, G24 …` 가 최상위로 나왔습니다.
> 선호하는 깊이(기본 62%)는 **설정 > 명당 기준** 에서 바꿀 수 있습니다.

> [!CAUTION]
> 좌표를 이용한 추정치일 뿐입니다. 음향·시야각·스크린 곡률처럼 좌표에 안 잡히는 요소나
> 상영관마다 다른 구조는 반영하지 못하므로, 실제로 그 영화관이 꼽는 명당과 다를 수 있습니다.
> 참고용으로만 쓰고 중요한 자리는 좌석표를 직접 보고 고르세요.

## 적응형 폴링

모든 회차를 같은 주기로 훑지 않습니다. 상영표 조회 한 번이면 그 날짜 전 회차의 잔여석을
알 수 있고, 잔여석이 늘어난 순간이 곧 누군가 취소한 순간입니다.

1. 오늘·내일 상영표는 매 주기 새로 받습니다 (날짜당 1회 호출)
2. 잔여석이 **늘어난 회차는 그 자리에서 즉시** 좌석표를 조회합니다 → `[취소표]` 표시
3. 나머지는 상황에 따라 간격을 달리합니다

| 구간 | 기준 | 확인 간격 (주기 20초 기준) |
|:---|:---|:---|
| 임박 | 상영 2시간 이내 | 20초 |
| 오늘/내일 | 24시간 이내 | 40초 |
| 3일내 | 72시간 이내 | 100초 |
| 여유 | 그 이후 | 240초 |

최근 취소가 있었던 회차는 ×0.4(더 자주), 거의 매진이면 ×0.7, 자리가 절반 이상 남았으면 ×2.
잔여석 수가 그대로면 좌석 구성도 그대로일 가능성이 높아 건너뛰되, 임박 회차는 2번·먼 회차는
6번마다 강제로 실제 조회합니다.

> [!NOTE]
> 실측 (월드타워 · 오디세이 · 3일치 109회차): **첫 주기 113회 → 이후 주기 2~3회 호출.**
> 같은 시간에 더 촘촘히 볼 수 있고 차단 위험도 낮아집니다.

## 예매 오픈 패턴 (언제 열리는지)

영화관들은 오픈 일정을 공지하지 않지만, 지금 예매가 열려 있는 마지막 날짜(horizon)는
관측할 수 있습니다. 이 값이 늘어난 순간이 곧 오픈 순간입니다.

이진탐색으로 현재 범위를 재고(45일 범위에 6~7회 호출), 날짜별 회차 수를 그려줍니다.
예매는 층이 나뉘어 열립니다:

```
│ D+0  08-28(금)  ████████████░░░░░░░░░░  25회차     ┐
│ D+4  09-01(화)  ██████████████████░░░░  38회차     ┘ 정규 편성
│ D+5  09-02(수)  ████████░░░░░░░░░░░░░░  17회차     ┐ 주요작
│ D+9  09-06(일)  ████████░░░░░░░░░░░░░░  18회차     ┘ 선행 오픈
│ D+10 09-07(월)  ░░░░░░░░░░░░░░░░░░░░░░  미오픈
```

기록이 쌓이면 요일·시각·주기·폭을 학습해 예측합니다. 여는 방식이 두 가지라 계산도 나눕니다:

| 패턴 | 판별 | 예측 방법 |
|:---|:---|:---|
| **batch** (주 단위로 왕창) | 이벤트 간격 > 2일 | 학습한 요일·시각으로 앞으로 굴려 목표일이 범위에 드는 시점 |
| **rolling** (매일 조금씩) | 이벤트 간격 ≤ 2일 | 현재 범위와의 차이만큼 뒤 |

```
│ 2026-09-08(화)  [예상] 2026-09-03(목) 10시 무렵
│               7일마다 7일치씩 여는 패턴 · 관측 3회 · 신뢰도 보통
```

> [!IMPORTANT]
> 예측은 **관측이 쌓인 만큼** 정확해집니다. 이력이 없으면 현재 범위만으로 역산하고
> `신뢰도 낮음` 으로 표시합니다. [헤드리스 모드](#헤드리스-모드-화면-없이-돌리기)를
> 작업 스케줄러에 걸어 `openlog.jsonl` 을 채워두는 것이 사실상 전제입니다.

<br>

## 감시 통계

쌓인 기록은 메뉴의 **감시 통계**에서 집계합니다. **잔여석이 늘어난 순간이 곧 취소**이므로,
그 시각을 요일·시간대로 모으면 *언제 지켜봐야 하는지* 가 나옵니다.

```
│ 기간      2026-08-29 ~ 2026-08-30
│ 관측      99줄   취소 37회 (+78석)   판매 62회
├──────────────────────────────────────────────
│ 취소가 잦은 때  (관측 시각 기준)
│   토 18시      ████████████████   7회 (+13석)
│   토 17시      █████████████░░░   6회 (+19석)
├──────────────────────────────────────────────
│ 취소가 잦은 회차
│   08-31 19:00 21관  ████████████  11회 (+24석)
```

기간은 오늘 · 7일 · 30일 · 전체 중에 고릅니다.

## 알림

- **소리** · Discord/Slack **웹훅** · **텔레그램** 봇 · 예매 페이지 **자동 열기**
- 기본은 **상태가 바뀔 때만** 알립니다. 팔렸다가 다시 비면 다시 알립니다.
- 소리는 Windows Media 폴더의 WAV 파일을 재생합니다 (설정에서 종류 선택).

알림 링크는 그 회차에 최대한 가까운 곳으로 갑니다. 브랜드가 URL 에 담아주는 만큼만 되므로
깊이가 다릅니다:

| 브랜드 | 링크가 닿는 곳 |
|:---|:---|
| **메가박스** | 그 회차 **좌석선택 화면** (`/booking/seat?playSchdlNo=…&brchNo=…`) |
| **CGV** | 그 회차 **상영시간 선택 화면** (`movNo` & `scnYmd` & `siteNo` & `scnsNo` & `scnSseq`) |
| **롯데시네마** | 그 회차 **상영시간 선택 화면** (`link_*` 파라미터) |

## 헤드리스 모드 (화면 없이 돌리기)

인자를 주면 화면 대신 한 줄 로그만 찍고 끝납니다.

```bash
python cinema_watch.py --radar --cinema 월드타워 --movie 오디세이 --once
```
```
2026-08-30 02:05:56  롯데시네마 월드타워 · 오디세이 · D+7 까지 (마지막 2026-09-06) · API 9회
```

| 인자 | 뜻 |
|:---|:---|
| `--radar` | 예매 범위를 재서 `openlog.jsonl` 에 남깁니다 |
| `--profile 이름` | 저장해 둔 감시 설정을 화면 없이 돌립니다 |
| `--brand` | `lotte` · `megabox` · `cgv` (기본 `lotte`) |
| `--cinema` | 지점 번호 또는 **이름 일부** (`1016` 또는 `월드타워`) |
| `--movie` | 영화 제목 일부 |
| `--once` | 한 번만 재고 끝냅니다 (스케줄러용) |
| `--interval` | `--once` 가 아닐 때 반복 주기 (기본 600초) |
| `--webhook` `--telegram-token` `--telegram-chat` | 오픈을 잡으면 알림 |
| `--list-cinemas` | 그 브랜드의 지점 번호·이름을 쭉 찍습니다 |

종료 코드는 정상 `0`, 조회 실패 `1`, 인자가 틀리면 `2` 입니다.

### Windows 작업 스케줄러에 걸기

10분마다 관측하도록 등록합니다 (경로는 실제 위치로).

```bash
schtasks /create /tn "cinema-watch radar" /sc minute /mo 10 /tr "pythonw D:\cinema-watch\cinema_watch.py --radar --cinema 월드타워 --once"
```

`pythonw` 로 걸면 검은 창이 뜨지 않습니다. 지우려면 `schtasks /delete /tn "cinema-watch radar" /f`.

### 어디서나 `cinema_watch` 로 실행하기

`cinema_watch.bat` 이 함께 들어 있습니다. 아무 폴더에서나 부르려면 이미 PATH 에 있는
`%LOCALAPPDATA%\Microsoft\WindowsApps` 에 얇은 런처를 하나 두면 됩니다.

```bat
@echo off
call "D:\경로\cinema-watch\cinema_watch.bat" %*
```

> [!CAUTION]
> 배치 파일 주석을 한글로 쓰면 cmd 가 콘솔 코드페이지로 읽다 깨뜨려 엉뚱한 명령으로
> 해석합니다. 그래서 `cinema_watch.bat` 의 주석은 영문으로 두었습니다.

## 설정

메뉴의 **설정**에서 전역 환경설정을 바꿉니다. 값은 `settings.json` 에 저장됩니다.

| 항목 | 설명 | 기본값 |
|:---|:---|:---:|
| 시작 배너 로고 | 배너 ASCII 로고 표시 여부 | 켜짐 |
| 배너 유지 시간 | 정보성 배너를 몇 초 보여줄지 (0~10초) | 3초 |
| 알림 소리 | 알림음 전역 스위치 (회차별 설정과 **둘 다** 켜야 소리가 남) | 켜짐 |
| 알림음 종류 | 알람 · 벨소리 · 알림음 · 차임 (`p` 로 미리듣기) | 알람 |
| 좌석표 폭 | 0 이면 터미널 폭을 그대로 사용 | 자동 |
| 명당 기준 | 스크린에서 몇 % 뒤를 좋아하는지 | 62% |

### 저장되는 파일

| 파일 | 내용 |
|:---|:---|
| `profiles.json` | 저장한 감시 설정 |
| `favorites.json` | 즐겨찾는 지점 · 상영관 · 영화 |
| `history.jsonl` | 잔여석 변동 기록 (감시 통계의 원본) |
| `openlog.jsonl` | 예매 범위 관측 기록 (오픈 예측의 원본) |
| `settings.json` | 전역 환경설정 |
| `errors.log` | 조회 실패 기록 |

모두 `.gitignore` 대상이라 커밋되지 않습니다.

## 사용하는 API

모두 로그인 없이 응답하는 공개 조회 엔드포인트입니다.

<details>
<summary><b>롯데시네마</b> — <code>multipart/form-data</code> 의 <code>paramList</code> 에 JSON 한 덩어리</summary>

<br>

| 용도 | 엔드포인트 / MethodName |
|:---|:---|
| 극장 목록 | `Cinema/CinemaData.aspx` / `GetCinemaItems` |
| 상영시간표 | `Ticketing/TicketingData.aspx` / `GetPlaySequence` |
| 좌석표 | `Ticketing/TicketingData.aspx` / `GetSeats` |

`GetPlaySequence` 는 `cinemaID="1|1|1016"` 형식, `GetSeats` 는 접두어 없이 `cinemaID="1016"`.

</details>

<details>
<summary><b>메가박스</b> — JSON POST</summary>

<br>

| 용도 | 엔드포인트 |
|:---|:---|
| 지역·지점 목록 | `/on/oh/ohb/PlayTime/selectPlayTimeMasterList.do` |
| 상영시간표 + 잔여석 | `/on/oh/ohc/Brch/schedulePage.do` (`brchNo1` 로 지점 지정) |
| 좌석표 | `/on/oh/ohz/PcntSeatChoi/selectSeatList.do` (`playSchdlNo` + `brchNo`) |

`brchNo1` 이어야 지점 필터가 걸립니다. `brchNo` 로 보내면 전국이 옵니다.

</details>

<details>
<summary><b>CGV</b> — JSON GET</summary>

<br>

실제 호스트는 `api.cgv.co.kr` 이지만 직접 부르면 401 이고, `cgv.co.kr/api/v1/booking/`
프록시로는 열립니다.

| 용도 | 엔드포인트 |
|:---|:---|
| 지역·극장 목록 | `/api/v1/booking/searchRegnList?coCd=A420` |
| 상영시간표 + 잔여석 | `/api/v1/booking/searchMovScnInfo` (`coCd`+`siteNo`+`scnYmd`+`rtctlScopCd=1`) |
| 좌석표 | `/api/v1/booking/searchIfSeatData` (`scnsNo`+`scnSseq`+`seatAreaNo=001`+`cusgdCd=01`) |
| 예매 가능 날짜 | `/api/v1/booking/searchSiteScnscYmdListBySite` |

예매 UI 는 회차를 고르는 순간 로그인을 요구하지만, 좌석 API 자체는 로그인 없이 열립니다.

</details>

### 세부 사항

- 롯데 `GetPlaySequence` 의 `BookingSeatCount` 는 예매된 수가 아니라 **잔여** 좌석 수입니다.
- 좌석 상태는 `SeatStatusCode`(0=가능, 50=예매완료)와 `BookingSeats` 로 함께 판단합니다.
- 같은 회차가 좌석 구역별로 여러 줄(예: `씨네패밀리` 18석 + `일반` 342석)로 내려오면 하나로 합칩니다.
- 이미 시작했거나 매진된 회차는 감시 대상에서 빠집니다.

## 참고

- API 호출 간격은 0.6초로 제한돼 있습니다. 확인 주기를 과하게 낮추면 차단될 수 있습니다.

  (Windows Terminal / PowerShell 7 권장).
- 한 바퀴가 확인 주기보다 오래 걸리면 화면에 알려줍니다. 상영관·요일·시간대를 좁히세요.
